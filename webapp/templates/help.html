🎮 Automation Runner — how it works

A short guide for first-time users. No prior setup knowledge needed — if you can plug in a phone and open a browser, you can run the tests.

❓ What is this?

The Automation Runner drives automated tests on the Sorry! World game running on a real Android phone. You pick what to run in this web page and click Run; the server does the rest and produces a report. Everything (the test scripts, the game licence, the database) lives on the central server — your laptop just needs a phone plugged in.

✅ What you need

1
An Android test phone — signed in with a test account.
2
A USB cable to connect the phone to your laptop.
3
Same network as the server — office Wi-Fi/LAN, or the company VPN if you're working from home.
4
A web browser — that's how you use this tool.

You do not need to install the test scripts or the game licence — those stay on the server.

▶️ Run a test (3 steps)

  1. At the top of the Runner, choose your Project, a Run type (see below), and the device you want to run on.
  2. Click Run (or Run here on your device's row).
  3. Watch the live console as it goes. When it finishes, open the Report to see each step and result.

If several people run at once, each run has its own row and log — you won't block each other (up to the licensed limit).

🔌 Add your device from a new laptop

If your phone is plugged into your laptop (not the server), onboard it once:

  1. On the phone, turn on Developer Options → USB debugging, then plug it into your laptop with the USB cable.
  2. On your laptop, open the Terminal app (macOS: press Cmd + Space, type “Terminal”, Enter).
  3. In the Runner click ＋ Add a device, copy the command it shows, paste it into Terminal and press Enter. It looks like: curl -fsSL http://<server>:8000/install.sh | bash It sets everything up automatically the first time (it may ask for your Mac password once). Leave that Terminal window open.
  4. On the phone, tap “Allow USB debugging” when it pops up.
  5. Your device turns green in the Runner — now pick it and click Run here.
Windows users: use the PowerShell command from the same panel instead (irm .../install.ps1 | iex).

📄 Your results

  • Report — an HTML page with every step and pass/fail, named by run type + date/time. Open it from the Report dropdown.
  • Screenshots — if the Screenshots toggle is on, each step is captured; download them all with the 📸 Screenshots button.

🏃 Run types

TypeWhat it does
smokeQuick sanity — a few key tests to check the build is healthy.
iapIn-app purchase flows — exercises the paid/shop features thoroughly.
regressionThe broader set — catches things that used to work but broke.
completeEverything — the full feature suite end to end.

You can also run a single test instead of a whole suite from the Single-test dropdown.

🛠️ If something goes wrong

  • Device doesn't turn green / not listed — check the USB cable, make sure you accepted the “Allow USB debugging” prompt on the phone, and that the Add-a-device Terminal window is still open.
  • Can't open the Runner page — you must be on the office network or VPN; use the server address your admin gave you (e.g. http://<server>:8000).
  • A run fails partway — open its log/report to see the last step; it's often a popup or a screen that changed in a new build. Share the report with the QA team.
  • Still stuck — ask the QA/automation admin; they run the server.

📖 Glossary

ServerThe always-on Mac that runs the tests and this web page.
Bridge / agentThe small helper that runs on your laptop so the server can drive the phone plugged into it.
AltTesterThe tool that lets the tests “see” inside the Unity game screens.
AppiumThe tool that taps and swipes the phone like a user would.
ReportThe results page produced after a run.
